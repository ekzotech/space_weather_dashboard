# Источники, хранение и тестовые данные

| Данные | Источник | Время свежего кэша |
| --- | --- | --- |
| Наблюдаемый и прогнозный Kp | [NOAA SWPC products](https://services.swpc.noaa.gov/products/) | 5 минут |
| Рентгеновский поток | [NOAA GOES](https://services.swpc.noaa.gov/json/goes/primary/xrays-1-day.json) | 1 минута |
| Сияние | [NOAA OVATION](https://www.swpc.noaa.gov/products/aurora-30-minute-forecast) | 5 минут |
| Архив за последние 30 дней | [NASA CCMC DONKI](https://ccmc.gsfc.nasa.gov/tools/DONKI/) | 30 минут |
| Текущая облачность | [Open-Meteo Forecast API](https://open-meteo.com/en/docs) | Запрос при проверке места |

У каждого кэша один ответ в памяти процесса. После сбоя сохранённый ответ можно выдать ещё до 30 минут сверх времени свежести. OVATION отдельно проверяет время наблюдения модели и скрывает процент, если ему больше часа. Пользовательские диапазоны архива и облачность запрашиваются без серверного кэша. Перезапуск сервера удаляет содержимое кэша. Последнее проверенное место и порог Kp хранятся в браузере, пока пользователь не очистит данные сайта.

## Обновление тестовых данных

1. Определите, какой публичный JSON изменился, и сравните его схему с `backend/src/noaa.rs`, `backend/src/nasa.rs` или `backend/src/aurora.rs`.
2. Добавьте минимальный обезличенный пример новой формы. `backend/fixtures/donki-gst.json` использует поля из GST, сокращённый список вложенных записей и синтетическое некорректное значение для проверки фильтра. В остальных тестах ответы источников собираются из коротких примеров прямо в тестах.
3. Проверьте пустые, отсутствующие и некорректные значения. Обновите пример OpenAPI при изменении контракта. В тестовые данные не включайте ключи и координаты реальных пользователей.
4. Запустите `cargo test --locked --manifest-path backend/Cargo.toml` и `npm run test:e2e --prefix frontend`. Синтетические тесты не обращаются к публичным источникам.
